# PartNest

面向个人电子 DIY 的元器件库存与 BOM 缺料分析工具：以导入的 BOM 为「项目」组织缺料分析与焊接工作台；
Tauri 2 + React + TypeScript + SQLite，交互式 BOM 在沙箱 iframe 中渲染，只通过带会话令牌的消息上报选择。

## 环境要求

- Node.js 与 pnpm 10（根 `package.json` 的 `packageManager` 已锁定）
- Rust stable 的 MSVC 工具链，以及 Visual Studio 2022「使用 C++ 的桌面开发」工作负载
- Windows 上无需手工配置编译器环境变量，脚本会自动定位并加载 `VsDevCmd.bat`

## 安装与开发

```powershell
pnpm install
pnpm dev            # 等价于 pnpm --filter @partnest/desktop tauri dev
```

## 验证

```powershell
.\scripts\verify.ps1
```

依次执行 `pnpm test`、`pnpm build`、`cargo test`、`cargo clippy --all-targets -- -D warnings`、
`cargo fmt --check`、`tsc --noEmit`、`pnpm --filter @partnest/desktop tauri build` 和 `git diff --check`。
验证使用 `tauri build --no-bundle -- --locked` 构建本地 EXE，不调用安装包工具。

Rust 相关命令在 `call VsDevCmd.bat -arch=x64 && set CC= && set CXX=` 的子进程中运行。全局设置了带空格的
`CC`（例如 `C:\Program Files\...\cl.exe`）时，`libsqlite3-sys` 的构建脚本会以
`failed to find tool "C:\Program"` 失败，因此这一步不可省略；环境引导逻辑与发布脚本共用
`scripts\msvc-env.ps1`。

## 本地 Windows release

```powershell
.\scripts\build_release.ps1
```

脚本检查 Windows x64 MSVC 工具链，以及 `apps/desktop/package.json`、`Cargo.toml` 和
`tauri.conf.json` 的应用版本是否一致，然后执行 `pnpm install --frozen-lockfile`、完整验证和 release 构建。
Rust 构建使用 `--locked`。任何检查失败时以非零状态退出，不复制新的发布产物。

产物：`dist/releases/v<版本>/PartNest-<版本>-windows-x64.exe`。脚本检查 EXE 的 x64 PE 标识并输出 SHA256。
这是本地 EXE，不创建安装包、不提交代码、不创建 Git 标签，也不上传远端 Release。运行需要 Windows WebView2 Runtime。
首次安装依赖可能需要联网。构建期间的编译器环境调整只作用于构建进程。

## 项目资料与备份

交互式原始 HTML、规范化配套表格和项目快照保存在 SQLite 中，并在同一事务中提交。
`interactive-bom-cache` 只保存打开工作台时生成的页面；删除或损坏缓存后，重新打开可从数据库重建。
导入时不会写渲染缓存，因此缓存目录不可写不影响保存项目；打开工作台时仍会报告文件写入失败。

`.db` 备份包含交互式资料，可在没有原文件和缓存的新目录恢复。备份前会检查资料，并从旧缓存补入缺失资产。
旧缓存不存在、摘要不符或与项目快照不一致时，备份失败并给出错误，不生成缺少画布的备份。
支持读取 schema 12 的旧备份：先复制到临时数据库再升级，不改写所选备份文件；旧交互式备份仍需要本机保留对应缓存才能补齐资料，缺失时恢复在替换当前数据库前失败。

文件读取与解析在后台任务中完成，提交阶段才获取数据库锁；补充导入在提交时再次检查项目状态和快照。
正在焊接或已有取用记录的项目禁止重复导入和补充导入，以保留库存记录与器件归属的关系；重命名仍可使用。

## 数据库迁移

新增迁移需要同时完成三处，否则迁移一致性测试和备份校验测试会失败：

1. 在 `apps\desktop\src-tauri\migrations\` 增加 `00XX_name.sql`，版本号必须连续。
2. 把该文件登记到 `src\db\mod.rs` 的 `migrations()` 清单（唯一清单，启动与测试共用）。
3. 同步 `src\backup.rs` 的 `CURRENT_SCHEMA_VERSION`；新增表或索引时补充 `require_table`/`require_index`。

## 项目与交互式 BOM 约定

- 「项目」页的「导入项目」打开导入窗口，里面两种来源各占一格，可各选一个文件也可只选一个：「可交互式 BOM（HTML）」与「普通 BOM 表（CSV / XLS / XLSX）」。两个都选时表格就是交互式导出的配套表格，合并成一个项目；只选交互式则先建出缺表格的项目，只选表格则先建出没有画布的项目，缺的那一半之后用项目头的「补充导入」补上。文件选择器按各自那一格过滤扩展名，格式不符只提示并禁用「创建项目」；点「创建项目」之前不做任何解析与写入。一次导入 = 一个项目，确认后先只读分析（表格必要时补一次字段映射），解析成功立即把结果作为快照写入数据库成为项目；同一份内容仍只对应一个项目；没有活动焊接会话和取用记录时，重复导入可刷新它而不会产生重复项。
- 导入本身不改变焊接会话。项目行的「打开焊接工作台」（或右击菜单里的同项）才把它变成活动会话：交互式项目从数据库资料生成桥接页面并渲染 iframe 画布，表格项目直接读数据库快照开启会话，没有画布，改在器件列表中按组选择位号。
- 点击左侧项目直接从数据库快照载入它的分析，原始文件被删除或移动后仍可打开；右击项目可重命名、打开焊接或删除。删除会连带移除缓存副本，但存在焊接会话记录的项目会被拒绝，以保证库存流水可追溯。
- 交互式 BOM 的配套表格不限于 CSV：导入窗口里那一格「普通 BOM 表」接受 `.csv`、`.xls`、`.xlsx`（calamine 按文件内容识别工作簿格式）。配套表格的位号必须与交互式导出完全一致，否则解析阶段就会报错，避免把两块板的资料合成一个项目。
- 只导入了一种来源的项目，之后可以用项目头的「补充导入」补上另一种：交互式导出补一张器件表格（表格与项目资产一起保存，重启后仍是合并结果），表格项目补一份交互式 HTML（就此获得 3D 画布，原表格继续提供器件数据）。补充导入会改写器件归属，所以该项目正在焊接、或已经记录过取用时会被拒绝（提示先退出/到库存流水撤销）；两种来源都齐了就不再提供该入口。
- 焊接工作台在没有活动会话（或缓存副本丢失）时提供「选择项目」弹窗，按项目 id 打开：表格项目读快照，交互式项目重新生成带新桥接令牌的页面。
- 「退出当前焊接」只结束会话：已取用的库存保持扣减、不自动退回，历史取用仍可在「库存流水」撤销以纠正错拿；桥接令牌随即失效，重新打开该项目的焊接会开始进度从零计的新会话。
- 焊接工作台只接受操作者的显式选择：交互式 BOM 来自文档内点击后的桥接上报，表格 BOM 来自器件列表；宿主侧同样校验令牌、位号归属、数量上限与消息频率。
- 器件列表的「数量/板面」按器件自身统计；点某一行就选中它实际所在的面（当前页签没有该器件时会自动切到它那一面），不再出现「底层器件在顶层页签下点不动」。
- 表格 BOM 没有板面列时，取用按操作者当前选中的板面记录；同一位号在同一会话内只扣减一次库存（切换板面重复提交会被拒绝），全部已取用时需撤销流水才能重新取用。
- 交互式 BOM 的画布在沙箱 iframe 中渲染，沙箱为 `allow-scripts allow-same-origin`：EasyEDA 查看器要启 WebGL 并使用自身存储，缺 `allow-same-origin` 会整块白屏。顶层导航、弹窗、表单、下载一律不开；asset 协议 scope 限定为 `$APPDATA/interactive-bom-cache/**`，画布读不到数据库等其它文件。画布仍按不可信文档对待：位号选择必须经会话令牌与归属校验，取用还要操作者在宿主侧确认。
- 注入的 `bridge-v1.js` 会把查看器自带的表头与元件表隐藏掉（`display:none`，不移除，原生搜索与行点击仍可用），只留 3D 板子撑满画布区；隐藏范围严格限定为画布祖先链之外的兄弟节点，并监听 DOM 重建后重新应用。
- 在 PartNest 里选中器件后，宿主把当前位号与板面发给画布：注入脚本先按需翻转查看器自己的顶层/底层视角（用 `is-select` 判断，已是目标面就不重复点），再点选该器件所在的那一行，让 3D 持续高亮。位号只认单元格自身的文本或首个子块，并跳过把整棵应用嵌进去的布局单元格。
- 缩放不自动做：查看器的「适应选中」在退化包围盒（如 0402 小元件）上会冲到极端放大，所以画布右上角提供「缩放居中」（按 `title="适应选中"`）与「复位视图」（按 `title="适应全部(K)"`）由操作者点。两类消息与高亮共用同一条通道：只接受来自宿主、令牌与当前会话一致的指令，动作只认 `fit`/`reset`；脚本自己发出的合成点击不会被回报成操作者的选择。
- 渲染缓存缺失或损坏时，从数据库自动重建；只有旧项目尚未保存原始资料且旧缓存不可用时，才需要恢复资料后重试。


## 库存删除

- 库存页面允许删除有剩余数量、库存流水或焊接记录的器件，操作前会提示剩余数量和影响。
- 删除采用逻辑归档：器件退出可用库存，盒位与 LCSC 编号可以重新使用；历史流水保留器件名称和数量。
- 删除时的数量仅作为历史快照保留，不再用于 BOM 匹配或焊接取用。已删除器件的历史取用不能撤销。
- 活动焊接会话保留已取用位号与累计进度，后续可以选择新的库存器件处理尚未取用的位号。
