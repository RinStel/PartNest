# PartNest 设计方案

## 1. 目标

PartNest 是面向个人电子 DIY 的本地元器件库存与 BOM 焊接辅助工具。

核心流程为：查看库存、定位盒位、检查 PCB 缺料、确认取用、扣减库存。

首期以 Windows 10/11 为验收平台。业务层保持跨平台。

## 2. 首期范围

首期实现以下功能：

- 管理离心管盒、盒位和元器件库存。
- 导入 EasyEDA 导出的本地交互式 BOM HTML。
- 解析 EasyEDA 导出的 CSV 或 XLSX BOM。
- 按 BOM 计算库存和缺料数量。
- 在 PartNest 内打开交互式 BOM。
- 根据当前选中的器件显示库存和盒位。
- 确认取用后扣减库存。
- 支持修改实际取用数量、追加取用和撤销取用。
- 缓存 BOM 文件并恢复焊接进度。
- 定期备份 `partnest.db`。

首期不实现以下功能：

- EasyEDA 扩展。
- 多块相同 PCB 的批量焊接。
- 账号、云同步或 Cloudflare D1。
- macOS 和 Linux 安装包验收。
- 模糊匹配结果自动扣减库存。

## 3. 技术方案

技术栈为 Tauri 2、React、TypeScript、Vite、shadcn/ui、Tailwind CSS、SQLite、pnpm workspace 和 Vitest。

Tauri Rust 后端负责：

- SQLite 访问和事务。
- 文件缓存和 SHA-256 计算。
- HTML 数据提取和桥接脚本注入。
- BOM WebView 隔离。
- 数据库备份和恢复。

React 主界面负责：

- 库存、收纳盒和 BOM 页面。
- 器件匹配和缺料结果展示。
- 焊接工作台交互。
- 取用数量输入和用户确认。

业务类型和规则放在独立 TypeScript package 中。界面不得直接执行任意 SQL。

## 4. 数据库

`partnest.db` 是唯一业务事实来源。数据库使用 SQLite，并启用外键和 WAL。

主要数据表如下：

| 表 | 责任 |
| --- | --- |
| `boxes` | 保存盒子名称和行列规格 |
| `parts` | 保存器件资料、库存数量和唯一盒位 |
| `bom_files` | 保存文件名、备注名、哈希和缓存文件名 |
| `welding_sessions` | 保存焊接会话和会话状态 |
| `welding_progress` | 按器件分组和板面保存取用进度 |
| `inventory_movements` | 保存入库、取用、调整和撤销流水 |

数据库要求：

- ID 使用 UUIDv7 文本。
- 时间使用 UTC。
- `parts.quantity` 必须是非负整数。
- `box_id + slot` 必须唯一。
- 非空 `lcsc_code` 必须唯一。
- 盒子规格调整不得删除已经占用的盒位。
- 库存扣减、流水写入和进度更新必须在一个事务中完成。
- 撤销操作必须写入反向流水。撤销操作不得删除原流水。

备份必须使用 SQLite Backup API 或 `VACUUM INTO`。程序不得直接复制正在使用的 WAL 数据库文件。

## 5. BOM 导入和缓存

用户选择本地 HTML 后，PartNest 执行以下操作：

1. 计算原文件的 SHA-256。
2. 将原文件复制到应用缓存目录。
3. 从 `window.files.bom_merge` 提取器件分组和位号数据。
4. 将数据转换为 PartNest 内部 BOM 类型。
5. 向缓存副本注入版本化桥接脚本。
6. 在独立 BOM WebView 中打开缓存副本。

程序不得修改原始 HTML。

已提供的交互式 BOM HTML 是解析基线。实际文件可以增加、删除或更改可选字段。解析器不得依赖固定的字段顺序或完整字段集合。

HTML、CSV 和 XLSX 解析器必须将输入字段转换为以下内部字段：

- 位号。
- 数量。
- 板面。
- 名称或参数值。
- 封装。
- 制造商。
- 制造商型号。
- 立创商城编号。

字段兼容规则如下：

- CSV 可以使用逗号或制表符分隔。解析器必须根据文件内容检测分隔符，不得根据扩展名确定分隔符。
- 分隔符检测必须忽略带引号字段中的逗号或制表符。
- CSV 解析器必须识别 UTF-8、带 BOM 的 UTF-8 和带 BOM 的 UTF-16LE。
- 解析器使用字段别名表识别常见的中文和英文字段名。
- 英文字段名匹配不区分大小写。
- 字段名匹配忽略字段名前后的空白字符。
- 未识别字段可以保留在当前导入结果中。未识别字段不得阻止导入。
- 缺少可选字段时，解析器必须保留器件记录，并将缺少的字段留空。
- 解析器无法确定字段含义时，程序必须要求用户完成当前导入的字段映射。程序不得猜测有歧义的字段。
- HTML 核心结构不兼容时，程序必须报告不支持的导出格式。程序不得加载部分解析结果。

有效器件记录必须满足以下条件：

- 记录包含正整数数量，或包含可以计算数量的位号列表。
- 记录至少包含立创商城编号、制造商型号或“名称或参数值 + 封装”中的一种识别信息。

数据库只保存以下 BOM 元数据：

- 原文件名。
- 用户设置的备注名。
- 文件哈希。
- 缓存文件相对名称。
- 最近打开时间。
- 已确认取用的最小进度信息。

数据库不得保存完整 HTML、完整 BOM 明细或 PCB 图形数据。

## 6. WebView 联动和安全边界

导入的 HTML 视为不可信内容。

- BOM WebView 不得访问数据库。
- BOM WebView 不得调用通用 Tauri API。
- 桥接脚本只能上报器件分组、位号、板面和会话令牌。
- Tauri 后端必须使用已解析的 BOM 数据校验桥接消息。
- 只有 React 主界面可以请求库存变更。
- 只有 Tauri 后端可以执行库存事务。

EasyEDA 更新导出格式时，PartNest 通过新增适配器版本兼容旧文件。缓存副本可以删除并重新生成。

## 7. 器件匹配

匹配顺序如下：

1. 使用立创商城编号精确匹配。
2. 如果 BOM 没有立创商城编号，则使用制造商型号精确匹配。
3. 使用“参数值或名称 + 封装”生成候选结果。

候选结果必须由用户确认。程序不得根据候选结果自动扣减库存。

首期一种器件只存放在一个盒位。程序不处理多盒位库存分摊。

## 8. 焊接和取用

选中器件不得修改库存。用户执行“确认取用”后，程序才扣减库存。

默认取用数量为当前器件在当前板面的 BOM 数量。用户可以在确认前修改实际取用数量。

顶层和底层必须独立记录：

- 顶层取用不得将底层标记为已取用。
- 同一个器件分组可以分别产生顶层和底层取用流水。
- 同一板面发生损耗时，用户可以追加取用。
- “全部”只用于查看和汇总。“全部”不是数据库中的板面状态。

每次确认取用必须记录 BOM 会话、器件分组、板面、位号、BOM 数量、实际取用数量、库存流水和确认时间。

库存不足时，程序不得产生负库存。程序必须保留用户输入，并显示库存不足状态。

## 9. 界面

主要页面包括库存、收纳盒、BOM 导入与缺料分析、焊接工作台、库存流水和设置。

焊接工作台包含：

- 主导航。
- 交互式 BOM 和器件列表。
- 当前器件、盒位、库存、位号、数量和确认操作。

器件列表要求：

- 用户可以拖动调整列宽。
- 列宽只保存在当前界面运行状态。关闭焊接工作台后，列宽恢复默认值。
- 程序不得将列宽写入数据库或配置文件。
- 表头保持可见。
- 数量列和状态列保持紧凑。
- 顶层、底层和全部视图可以切换。
- 顶层和底层分别显示取用状态。

界面文案必须简短。界面只显示完成任务所需的标签、状态和数值。只有操作存在不可逆后果、状态冲突或真实歧义时，界面才显示说明。

## 10. 验收条件

- 程序可以解析已提供的交互式 BOM HTML 样例。
- CSV、XLSX 或 HTML 的可选字段发生变化时，程序仍可以导入满足有效器件记录条件的数据。
- 逗号分隔和制表符分隔的 CSV 可以生成相同的内部 BOM 数据。
- 字段含义存在歧义时，程序会要求用户完成字段映射。
- 程序可以区分顶层和底层器件实例。
- 选中器件不会修改库存。
- 确认取用会按用户输入的数量扣减库存。
- 同一个器件分组可以分别完成顶层和底层取用。
- 用户可以追加取用并撤销取用。
- 精确匹配和候选匹配具有不同状态。
- 程序不会根据候选匹配自动扣减库存。
- 重新打开 BOM 后可以恢复焊接进度。
- 原始 BOM 文件保持不变。
- 用户可以拖动调整器件列表列宽。
- 重新打开焊接工作台后，器件列表列宽恢复默认值。
- 数据库备份可以恢复为有效的 `partnest.db`。
