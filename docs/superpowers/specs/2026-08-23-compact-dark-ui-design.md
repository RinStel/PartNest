# PartNest 紧凑型深色界面设计

日期：2026-08-23
状态：待用户审阅

## 1. 目标

将现有界面重构为紧凑型桌面工具。界面必须提高信息密度、操作效率和跨页面一致性，不得改变已实现的库存、BOM、焊接、流水和备份业务语义。

首期验收窗口为 `1280 × 800 px`。界面在该尺寸下不得出现页面级横向滚动、主要操作遮挡或无法访问的表单字段。

## 2. 视觉方向

- 应用自有界面使用固定深色主题。
- 背景使用深灰黑，不使用纯黑。
- 层级主要通过背景明度、边框和分隔线表达，不使用大面积阴影卡片。
- 默认正文为 `13 px`；辅助文字和表格可以使用 `12 px`。
- 常规控件高度约为 `30 px`；顶部工具栏高度为 `40 px`。
- 蓝色表示选中或主要操作；绿色表示成功；黄色表示警告；红色表示危险。
- 状态不得只依赖颜色表达，必须同时显示文字或图形标记。

交互式 BOM 保持导出 HTML 的原始浅色内容。应用不得修改、反色或向原文件写入样式。焊接页使用中灰边框和独立画布承接浅色 BOM，降低深色外壳与浅色内容之间的明暗突变。

## 3. 应用框架

### 3.1 顶部工具栏

顶部工具栏固定为约 `40 px`。工具栏显示应用名称、当前页面名称、页面主要操作和必要状态。页面内容区不得重复显示同一层级的大标题。

### 3.2 左侧导航

- 展开宽度约为 `152 px`。
- 折叠宽度约为 `44 px`。
- 展开状态显示图标和文字；折叠状态只显示图标，并提供可访问名称或提示。
- 用户可以手动折叠或展开导航。
- 折叠状态只在当前应用运行周期内保存，不得写入 `localStorage`、Tauri storage 或 SQLite。

### 3.3 内容区

内容区采用“页面工具栏 + 主内容”的统一结构。页面工具栏承载搜索、筛选、新增、导入和备份等主要操作。主内容优先使用表格、分栏或网格，不使用无信息价值的大卡片。

## 4. 基础组件

建立统一的深色桌面组件规范，并在全部页面复用：

- 按钮：主要、次要、危险和纯图标四类。
- 输入控件：文本、数字、选择框、搜索框和文本域。
- 数据表格：紧凑行高、固定表头、悬停、选中、空状态和操作列。
- 状态标签：成功、警告、错误、中性和进行中。
- 弹窗：用于确认和短表单。
- 右侧抽屉：用于器件新增和编辑等字段较多的表单。
- 行内反馈：用于加载、保存成功和可恢复错误。

组件必须统一焦点样式、禁用状态、校验状态、边框、圆角和间距。不得继续使用影响所有页面的裸 `nav`、`main`、`input` 或 `table` 元素选择器作为主要样式接口。

## 5. 页面设计

### 5.1 库存

- 页面工具栏显示搜索、筛选和“新增器件”。
- 主体使用完整器件表格。
- 表格显示名称、分类、封装、制造商、MPN、LCSC、盒位、库存和操作。
- 新增和编辑使用右侧抽屉。
- 抽屉表单包含现有业务支持的全部元数据字段。
- 删除、库存调整和元数据编辑必须保持现有审计与版本约束。

### 5.2 盒位

- 左侧显示盒子列表。
- 右侧显示选中盒子的槽位网格。
- 盒子新增和编辑使用紧凑弹窗。
- 槽位状态同时显示占用状态和数量，不得只依赖颜色。
- 删除操作必须保留现有占用检查。

### 5.3 BOM 导入与分析

- 页面工具栏在一行内显示文件选择、备注名和导入操作。
- 只有解析结果为 `NeedsMapping` 时显示字段映射弹窗。
- 分析结果直接显示为表格，包含器件、封装、BOM 数量、库存、缺料、匹配状态和盒位。
- 候选匹配必须保留显式确认操作。
- 页面不得显示通用教学说明。

### 5.4 焊接工作台

- 主工作区左侧约占 `65%`，显示浅色交互式 BOM 画布。
- 右侧显示当前选中器件、盒位、库存、位号、BOM 数量、取用数量和确认操作。
- 顶面与底面使用分段切换，并分别显示独立进度。
- `all` 只显示摘要，不提供提交操作。
- “确认取用”按钮必须显示实际扣减数量。
- 确认失败后必须保留用户输入。
- 器件列表放在底部可折叠区域，避免压缩主要取用面板。
- 器件列表列宽保持可拖动，范围为 `72–480 px`，且只在当前组件挂载周期内保存。

### 5.5 库存流水

- 页面工具栏显示必要筛选。
- 主体使用按时间倒序排列的紧凑表格。
- 表格显示器件、变化量、变化前、变化后、原因和 BOM 备注名。
- “撤销取用”作为行内次要操作，只对后端判定可撤销的流水显示。

### 5.6 设置

- 使用“数据与备份”和“界面”两个分组。
- 不使用大面积卡片。
- 备份与恢复保留显式文件选择和现有安全校验。
- 首期界面主题固定为深色；本设计不增加主题持久化或主题切换。

## 6. 交互规则

- 危险操作使用确认弹窗。
- 普通保存和确认取用不得增加无必要的二次确认。
- 表单的主要操作支持 `Enter`；弹窗和抽屉支持 `Esc` 关闭，但存在未保存输入时不得静默丢失。
- 加载、空状态和错误使用简短行内反馈。
- 说明性文案仅在操作有真实歧义或数据风险时显示。
- 焊接选择不得触发库存变化；只有“确认取用”可以提交扣减。
- 深色主题不得修改交互式 BOM iframe 内的内容。

## 7. 状态持久化边界

以下状态只保存在 React 组件或应用运行周期内：

- 左侧导航折叠状态；
- 抽屉和弹窗开关状态；
- 表格临时列宽；
- 页面筛选和当前选择。

本次界面重构不得为这些状态新增 SQLite 表、Tauri storage 或 `localStorage` 写入。

## 8. 开发启动修复

当前 `pnpm dev` 启动时，Vite 默认监听 `5173`，但 Tauri `devUrl` 等待 `1420`。实施时必须统一端口配置，并验证一条命令可以直接打开 Tauri 窗口。

## 9. 验收与测试

必须保留全部现有业务测试，并增加以下界面测试：

- 主框架在导航展开和折叠状态下正确显示。
- 导航折叠状态在当前运行周期内保留，重启后恢复默认值。
- 库存新增和编辑抽屉显示完整字段。
- 盒位列表和槽位网格在 `1280 × 800 px` 下无页面级横向溢出。
- BOM 导入工具栏和字段映射弹窗状态正确。
- 焊接页保持约 `65/35` 主布局，iframe 仍只有 `allow-scripts` 沙箱权限。
- 顶面和底面状态独立，失败确认保留数量输入。
- 表格表头与数据列对齐，临时列宽在重新挂载后复位。
- 深色主题覆盖应用自有页面，交互式 BOM 内容不被修改。
- `pnpm dev` 直接启动 Tauri 应用，不再等待错误端口。

最终验证必须执行前端测试、TypeScript 检查、前端构建、Rust 回归、Tauri 开发启动和 `git diff --check`。Windows 10/11 人工业务验收、真实交互式 BOM DOM 差异和真实用户 BOM 哈希保留仍是独立发布门槛，不得因界面重构宣称通过。
